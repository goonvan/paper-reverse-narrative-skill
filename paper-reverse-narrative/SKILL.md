# 逆向叙事论文写作工作流 (Reverse-Narrative Paper Strategy)

适用：AI×科学/工程交叉方向，实验已全部完成、记录散落于实验日志，需要把"穷举试错史"重构为"假设驱动设计"的正向论文故事线。核心思想：**论文讲的是一条干净的逻辑链，而不是真实的探索顺序**——但链上每个环节都必须有真实数据兜底。

## 铁律（不可违背）

1. **只用真实实验记录 + 可核验文献**。每条主张必须有落盘出处（文件/日志/评估 JSON）。引用文献必须给出标题/期刊/年/卷/页/DOI 并逐条核验（CrossRef API 免费可查 DOI 真伪）；核验不了标【待核验】，**绝不编造文献、数据、DOI**。
2. **三类内容显式区分**：【已有实验证据】/【合理推断】/【建议补做实验】；证据强度标注 强/中/弱/待补。
3. **正向叙事 ≠ 隐瞒局限**。失败探索史不进主线、不作贡献陈述、禁用"我们试了 X 失败了"句式；失败模式只允许两种合法形式：①related work 里引文献级失败模式（"纯数据代理长时漂移是文献共识"）；②limitation 节如实披露本工作边界（评测域、后处理、失效工况）。**省略失败史 ≠ 隐瞒局限。**
4. **对照实验数字在方法节只作"设计选择的依据"**，数值擂台留给结果节。
5. **消融粒度匹配审稿人背景**：应用领域期刊的审稿人关注"架构增减/有无对照/成本分解"，不做 ML 科班式的机制证伪实验。

## 五段工作流 (A–E)

### A. 对标文献检索（"最新且最对标"1 篇）
- 范围：目标刊群 + 近 3 年；先建候选池（5–8 篇），逐篇核验存在性。
- **加权评分表**：体系/问题相似 30% · 任务相似 25% · 方法相似 20% · 评价指标 15% · 消融范式 10%（权重可按领域调）。
- 选出 1 篇后明确列出**"能照搬什么 / 不能照搬什么"**。
- 务必争取全文核验：摘要和二手综述会漏掉决定性定位事实（例：某对标工作实际只预测部分状态量、评估视程极短、外推仅定性——这些恰是你的 gap 锚点）。

### B. 对标文拆解
故事线六句骨架（问题→gap→洞察→方法→验证→结论）/ 引言逻辑链 / 模块表 / 实验矩阵 / 消融表 / 可迁移范式。**其范式缺口（无消融、无 CI、无多种子、无成本表、外推定性）= 你超越它的清单**。

### C. 逆向故事线
- 标题候选 3 型：①贡献入题型 ②方法驱动型 ③泛化+边界诚实型，让用户选。
- 摘要六句：问题 / Gap（对照 B 节精确表述）/ 洞察（2–4 个物理或结构假设）/ 方法 / 结果（预注册门指标）/ 贡献。
- **设计↔证据映射表**：每个设计决策一行 = 正向动机 | 真实出处 | 强度。
- **故事线完整性自检表**：每条主张 → 证据 → ✅可写 / ⚠️需补。⚠️ 项直接进入 D。

### D. 消融就绪度盘点 → 最小补做集
先盘点"故事线需要的消融是否已有落盘数据"——经验：**主线阶梯消融往往已散落在各轮实验记录里**，真正要补的很少。逐项标重要性（必做/高/中/低）+ 成本 + 本地/服务器。常见必做项：
- **成本分解表**（对标工作若有效率表，这就是准入件）：CFD/实验成本、训练成本（分级）、推理计时、加速比；全部用实测锚点，外推处标注【外推】。
- **集成/模块留一 (leave-one-out)**：堵"每个组件都必要吗"之问；集成阶梯只回答了"加了有用"，LOO 才回答"去了会伤"。
- **关键设计选择的有无对照**（如条件注入方式、约束施加位置）。

### E. 写作大纲
表格清单、图清单、审稿人 Q&A 预演（每个可能被攻击的弱环配一句防御）、红线声明表（哪些话绝不能说：无来源数字、夸大外推、隐藏评测域）。

## 方法节叙事模板（两套已验证句式）

**① 顺序设计问题结构**：把试错史改写为 4–5 个顺序设计问题，每节统一句式 **"对比消融了…最终选择…因为数据…"**。示例骨架：
> 基座架构（多基线统一协议对比）→ 时空/特征表达（两种编码对照）→ 条件注入方式（A vs B 对照）→ 残差消除（级联深度 + 组件留一）→ 物理/约束一致性（软约束进训练 vs 硬约束进推理的分工）。

**② 架构提出段（"谱系综述→启发→提出"手法）**：
1. 逐架构综述其优劣，每条配经典引文——优劣表述保持文献级（如"纯卷积感受野有限""谱方法对高频结构有平滑偏置"），不点自己的失败史；
2. 用领域物理/结构洞察做过渡（"该问题具有天然的尺度分离结构 → 应解耦处理"）；
3. **创新声明句（两句式）**：
   > "本研究创新性地基于 X 架构，开发了一种用于 Y 的 Z 方法。通过将 A 的能力与 B 的优势（与 C）相结合，有望为 Y 问题提供更高效、更精确的解决方案。"
   ——若摘要已有实测数据兜底，把"有望"换成"实现了"，语气更实。

## 执行要点

- **先列"需要用户补充的信息清单"再动手**（时间窗、是否允许联网、有无原文、消融预算、输出形式、是否写负向结果）。
- 补做实验按"本地评估级（便宜）→ 服务器训练级（贵）"分级安排；长任务先跑起来再做本地分析。
- 每完成一项补做，立刻回填策略文档的对应行（❌→✅ + 关键数字），保持自检表鲜活。
- 交付物建议：独立策略文档（A–E 全结构）+ 补做实验结果文档（设计/结果表/论文解读口径）分离，前者是路线图、后者是数据源。
